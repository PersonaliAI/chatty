## Overview

Send a message to your bot and get a response based on its knowledge base, guardrails, and language settings. The bot maintains full conversation history within a `session_id`.

**Required scope:** `chat`

<Note>
  Pass the same `session_id` on every request to keep the conversation in context. If you omit it, a new session is auto-generated and returned in the response.
</Note>

## Request body

<ParamField body="text" type="string" required>
  The user's message. Max 4,000 characters. Control characters are stripped automatically.
</ParamField>

<ParamField body="session_id" type="string">
  Conversation thread identifier. Omit to start a new session — the generated ID is returned in the response. Reuse the same ID to continue an existing conversation.

  We recommend using a stable identifier from your system: a user ID, visitor UUID, or database row ID.
</ParamField>

<ParamField body="visitor_timezone" type="string" default="UTC">
  IANA timezone of the visitor (e.g. `"America/New_York"`, `"Europe/London"`). Used by the bot when answering time-sensitive questions or scheduling meetings.
</ParamField>

## Response

<ResponseField name="reply" type="string">
  The bot's text reply.
</ResponseField>

<ResponseField name="session_id" type="string">
  The session ID for this conversation. Pass this back in your next request to continue the thread.
</ResponseField>

## Managing sessions

Sessions are lightweight — there's no explicit "create session" call. Start a conversation by picking any unique ID:

```python
import uuid

# Per-visitor session
session_id = f"visitor-{user_id}"

# Per-page-load session (fresh conversation every visit)
session_id = f"anon-{uuid.uuid4()}"

# Named demo session
session_id = "demo-1"
```

To reset a conversation, call [`DELETE /api/v1/conversations/{session_id}`](/api-reference/conversations/delete).
